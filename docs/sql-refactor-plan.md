# SQL Layer Refactor Plan: sqlx runtime → Diesel

Status: proposed. Owner decisions recorded: **delete `localize_images`**
(image localization is dropped entirely), fix the N+1s as part of the
translation, keep the existing SQL migration files.

## Goals

1. Replace hand-written SQL (`sqlx::query*`, ~106 call sites) with Diesel
   2.3 DSL — compile-time-checked queries against a generated `schema.rs`.
2. Remove chapter image localization (`localize_images`, the `images`
   table, `GET /api/images/{id}` serving of downloaded bytes) and with it
   the P0 issue found in review: `upsert_chapters` holds a SQLite write
   transaction across network downloads (~seconds to minutes), blocking
   every other writer.
3. Fix the two N+1 query patterns during translation:
   - `list_books` → one `files_of_book` query **per book**;
   - `list_series` → one `COUNT(*)` **per series**.
4. Keep behavior identical: same endpoints, same visibility semantics,
   same timestamp format, same e2e results.

## Non-goals

- No schema changes beyond dropping `images` (migration files stay as-is;
  they remain plain SQL run by `sqlx::migrate!`).
- No FTS5 / search upgrade (revisit if the library grows past ~10⁴ books).
- No change to the frontend/API contract except removing `/api/images/{id}`
  (see D1 below).

## Key design points

### D1 — Image localization removal

- Delete `localize_images` + `remote_image_urls` + `download_image`; plugin
  chapter HTML keeps remote `<img src>` URLs (the frontend already renders
  them with `referrerPolicy="no-referrer"`).
- **Keep** `GET /api/images/{id}` for now: already-materialized chapters
  reference those URLs; deleting the endpoint would break existing wenku8
  books until re-materialization. Serve from disk, no DB lookup fallback
  needed (the row is authoritative). A later cleanup commit can drop the
  table + endpoint once libraries are re-materialized.
- New migration `0010_drop_images.sql`: `DROP TABLE images;`
  (bytes on disk under `data/files/images/` are gitignored data, left in
  place; a note in docs tells operators they can delete the directory).

### D2 — Stack

```toml
diesel = { version = "2.3", features = ["sqlite"] }
diesel-async = { version = "0.7", features = ["sqlite"] }  # SyncConnectionWrapper
```

- Connections: `SyncConnectionWrapper<SqliteConnection>` behind
  `deadpool` (`AsyncDieselConnectionManager`), WAL + foreign_keys +
  `synchronous=NORMAL` preserved from today's connect options.
- Migrations unchanged: `sqlx::migrate!("./migrations")` still runs at
  startup (Diesel never sees them).
- `schema.rs` is generated by `diesel print-schema` and **committed**.
  New justfile recipe `just schema` regenerates it; the convention
  "run `just schema` after adding a migration" goes into AGENTS.md.
- Compile-time verification needs no `DATABASE_URL` at build time
  (schema.rs is checked in) — nix-friendly like today.

### D3 — Known caveats we accept / work around

| Caveat | Mitigation |
|---|---|
| `SyncConnectionWrapper` futures are not cancellation-safe (diesel-async#281): dropping a future mid-transaction then reusing the connection can panic | Never hold transactions across user-controlled await boundaries longer than necessary (already true after localize_images removal); wrap transaction bodies so cancellation lands between statements where possible; documented in the service module docs |
| Per-query `spawn_blocking` hop | Irrelevant at SQLite/local-disk latency |
| `CASE WHEN excluded…` upsert guard | Rewrite as `coalesce(nullif(excluded(content), ""), content)`; declare `nullif` once via `sql_function!` (declarative signature, no raw SQL string) |
| `strftime('%Y-%m-%dT%H:%M:%fZ','now')` explicit UPDATE in sessions.rs | Generate the same-format timestamp on the Rust side and bind it (table defaults stay DB-side) |

## Phases (one feature = one commit)

### P0 — `refactor(api)`: remove image localization
Delete `localize_images` path; migration 0010 drops `images`; keep the
images endpoint serving existing bytes; update `docs/plugins.md`; e2e
re-check that wenku8 illustration chapters render from remote URLs.

### P1 — `feat(server)`: Diesel infrastructure
Dependencies, `just schema` + committed `schema.rs`, pool swap to
diesel-async/deadpool behind the existing `LibraryService` constructor,
error mapping (`diesel::result::Error` → `ApiError::*`). No call sites
moved yet — server boots and passes tests against an empty Diesel surface.

### P2..P5 — `refactor(server)`: translate module by module
Order chosen by blast radius (small → large), each its own commit, each
keeping `cargo test` + e2e green:

1. **auth + db seed** (3 call sites)
2. **sessions + shares routes** (14 sites; includes the Rust-side
   timestamp change and the LEFT JOIN view query)
3. **plugins service** (7 sites)
4. **library service** (~81 sites; split into sub-commits if useful:
   acquire/upload paths first, then read paths, then series)
   - During this phase, replace both N+1s: `list_books` batches file
     loading with one `IN`-filtered query + Rust grouping; `list_series`
     computes counts with a single grouped query.
   - The parameterized switches (`(? OR visibility='public' …)`,
     `(f.source = ? OR ? IS NULL)`) become idiomatic conditional filters
     (`into_boxed()` + `if let Some(...)`), which is type-checked — the
     reason dynamic assembly is safe again.

### P6 — `chore(server)`: retire runtime sqlx
Remove `sqlx` runtime query usage (keep `sqlx-migrate`/`migrate!`),
drop now-dead `rows.rs` FromRow derives replaced by Diesel `Queryable`
selects into the same structs, set `synchronous=NORMAL`, put
`ensure_titles`' DELETE+UPDATE pair into one transaction.

### P7 — `docs`: conventions
AGENTS.md progress log + the `just schema` rule; this document marked
implemented.

## Verification per phase

- `just fmt && just check && just test`
- Frontend untouched except nothing — API contract stable (only
  `/api/images/{id}` semantics unchanged in P0).
- e2e scripts after P0, P2, P4, P6: register/login, upload txt+epub,
  plugin materialize (mock source), session create/update, share flows,
  series split acquisition, visibility matrix.
- Manual live check (wenku8 3617) after P0 and P4: materialize, lazy
  chapter pull, illustrations render from remote URLs.

## Risks

- **Behavior drift in translation** (bind order, LIKE escaping, ordering):
  mitigated by the static-SQL discipline already in place making each query
  a 1:1 mapping, plus the e2e suite.
- **schema.rs drift**: mitigated by `just schema` convention + a CI-ish
  check (`just check` can diff regenerated schema.rs).
- **Cancellation panic risk** (D3): low traffic single-instance deployment;
  revisit if it ever surfaces.
